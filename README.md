# BewlyCatAntiJunk

基于 [BewlyCat](https://github.com/keleus/BewlyCat) 的个人衍生浏览器扩展，在上游 Bilibili 页面优化功能的基础上，增加 AI 评论过滤，识别并折叠明显低质量、无意义、辱骂攻击和占楼评论。

BewlyCat 基于 [BewlyBewly](https://github.com/BewlyBewly/BewlyBewly) 开发。本项目沿用两者的代码与功能，主要新增反垃圾评论过滤，由个人独立维护，不代表上游官方版本。

## AI 评论过滤

支持原生评论、楼中楼及动态评论，使用 DeepSeek V4.1 Flash（`deepseek-flash`）。

在「设置 → Bilibili → 评论 → AI 评论过滤」填写 API Key，开启并保存，可测试连接、查看系统提示词和拦截原文。密钥与记录仅保存在扩展本地。启用后将评论及必要语境发送至 DeepSeek。

评论按批次编号，AI 必须逐条返回保留、屏蔽或疑难复判；缺项、重复编号和无效结果不会当作放行。内置规则按跨视频的表达行为积极屏蔽，优先减少漏杀、允许一定误杀；索取点单、消费表态、个人展示等不因含技术细节或问句自动豁免，清空案例库也不移除内置偏好。成人用语、荤段子本身不是屏蔽理由，未知图片不臆测。只有具体缺失信息能改变判断时才进入第二轮，补充可用语境后独立判断，不设比例硬上限，每条在同一规则及语境版本下最多两轮。有具体反感行为依据且无明确保留依据时屏蔽，纯粹缺信息则保留。接口或格式异常保持评论显示并标记出错，可手动重试。拦截内容可点击展开，记录最多保留 200 条并受容量限制。

带真实附图的单表情、短配文默认保留，避免漏掉以图片为主要内容的幽默；文字本身明确辱骂、广告或引战时仍可拦截。仅向 AI 传递附图标记，不发送图片；正文里的行内表情不算附图。

判断区分根评论、直接父评论及缺失语境，动态使用实际正文和转发关系；语境补齐后重检相关评论。判断结合视频与父评论的讨论目的：识别夹带挤兑的纠错、圈子身份起哄、借谦虚炫耀、用个人习惯否定别人需求，以及把公共设备管理等事件转成晒软件、晒配置或个人折腾的支线；同样的技术建议和求助在对应教程、排障讨论中保留。星星眼等表情结合正文和父评论判断，不能单独作为恶意标记。案例总结保留场景限制，不按年龄、学生身份、游戏名或小众软件推断评论者类型。

「注入视频元数据」默认开启，结合标题、时长、UP 主、简介和发布日期，筛掉与视频无关的品牌拉踩等垃圾内容；可关闭并保存，此时仅发送评论和父评论，当前评论会重新检测。可开启「检视模式」保留命中评论并标黄。AntiJunk 的独立导入导出位于「设置 → 关于」，包含配置和拦截记录，默认不导出密钥。

「彻底清空记录与缓存」会删除拦截记录、判断和视频元数据缓存，重置统计与错误状态，并取消旧请求。保留密钥和设置，当前评论恢复显示，新评论或刷新页面后继续检测；「清空记录」仅删除记录。

检视模式显示每条评论的检测状态：⚪️尚未发送、🟡已发送等待回复、🟠补充语境复判、🟢批准、🔴拒绝、⚫️出错后保留。可用「⊘」标记应屏蔽，展开被屏蔽评论后或在检视模式用「✓」标记应保留；检视状态可查看判断类别与轮次。案例库可撤销具体反馈。

「个人屏蔽案例库」支持增删带保留／屏蔽标签的原案例、编辑压缩指导、红色按钮一键清空。总结会将已有指导与新案例语义压缩成一段话，复核是否泛化/遗漏；生成、复核与保存均成功后才删除原案例，失败或内容变更则保留原内容。新增原案例最多 50 条、总量 64 KB，指导最多 6000 字符，均随 AntiJunk 独立备份保存。总结用于压缩，删除后不另建原案例归档，也不再保证原条目的精确匹配；后续靠压缩指导判断。v2 备份兼容导入 v1，旧案例视为屏蔽案例，默认不导出密钥。

每组评论数量可设置为 1–50（默认 10），每秒最大请求数可设置为 1–20（默认 1）。后台最多同时进行 3 个模型请求，首轮优先，标签页轮转调度；检测、二轮复判、语义总结、复核、连接测试和重试共享滚动一秒限额。相同判断的排队及在途请求合并，完整输入按容量拆批。取消或切换页面时解除订阅，无剩余订阅的任务取消；认证或余额错误暂停请求，保存设置后恢复。具体案例反馈只重检相关评论，摘要变化才整体失效。设置显示轮次数量、缓存命中、请求数和累计等待时间。

## 功能结构

AI 评论过滤实现集中于 `src/features/antiJunk/`，包含判断规则、请求调度、存储、设置及原生／动态评论适配。上游入口只保留初始化接线，动态评论组件仅绑定必要状态和控件。
